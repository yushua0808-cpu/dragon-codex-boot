# Windows 0.2.7 交付与验收记录

2026-10-27：用户反馈 0.2.7 连续六次测试全部成功。未逐次记录显示器、冷启动/已有实例、是否使用重试按钮，因此不能把这六次等同于全部验收矩阵通过。此前间歇性窗口消失原因仍未查明，不认定为网络故障。

## 最终行为

使用物理显示器坐标和 DPI 感知放置；auto 优先已有应用所在显示器，否则主屏。播放器限制在可见工作区。窗口通过稳定性检查后绑定；校验应用包、进程和真实顶层窗口，自动启动请求每次运行最多一次。内容采样仅作辅助，实际界面显示后不再退回等待。前台激活被拒时提供点击入口；没有窗口时提供手动恢复，启动十秒后可重试、两次间隔至少十秒、每次运行最多两次。Esc 无可用窗口时退出。

## 已知证据及限制

0.2.6 日志中，一次窗口内容已加载而 SetForegroundWindow 被拒，用户点击成功；另一次窗口在绑定前消失。0.2.7 增加丢失窗口身份、同包进程快照及显式手动恢复。不能声称诊断日志或手动恢复修复了官方应用窗口消失的根因。

自动化结果：22 条几何/配置、80 条生命周期/多屏、33 条隔离入口断言通过；605 个关键帧与12个放置案例通过。真实 WPF 恢复流程通过，AppLaunch 注入、程序模拟调用用户操作路径，未在该测试中重启官方 Codex。实际运行补充证据为用户连续六次成功。

## 部署

完整解压交付包到新目录，退出旧社区启动器，运行 DragonCodexBoot/DragonCodexBoot.exe。保留 EXE、launcher.json、media/startup.mp4 相对目录关系，不直接从 ZIP 内运行。自定义七秒 MP4 和现有配置参数保留。不要复用曾在故障 D 盘上损坏的旧 EXE/ZIP。交付不修改官方应用、快捷方式或原安装。

## 人工验收

分别核对主屏、副屏；Explorer 位于不同屏幕；PowerShell 运行；冷启动、已有窗口、最小化已有窗口。确认动画完整可见、无永久最后一帧、等待提示能退出；无窗口时验证手动重试，前台激活受限时验证点击进入。冷启动前自行正常退出 Codex，不要强制结束活动会话。保留 logs/launcher.log。

## 回滚

退出新版启动器，恢复使用之前的目录或官方原启动方式。新版独立目录可在确认无进程占用后删除。由于未覆盖原安装和快捷方式，无需恢复官方文件。源码提交和基线至本版的补丁用于代码回滚。
