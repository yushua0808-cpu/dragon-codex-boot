# 0.2.4：修复画面检查阻塞与手动进入无效

用户在 0.2.3 多次停在 MP4 末帧和“Codex 界面仍在加载”，不能进入 Codex。日志持续记录 `outer-ink=0.0000`；后续有一轮内容检查通过，但前台激活仍被拒。另有最小化 HWND 的客户端变成 `(-32000,-32000,160,28)`，被旧尺寸过滤误判为实例丢失。

这是 0.2.3 把不可靠的画面采样当作硬性启动条件引入的回归。PrintWindow 取到平坦画面并不能证明程序尚未加载。此前“跳过”也走同一个内容门槛，实际上无法绕过等待。本版优先恢复可进入性。

## 现在的行为

- 画面分析只辅助实时缩略图过渡。动画结束后若目标窗口身份正确、响应且稳定，最多再等待 3 秒，随后允许交接，不因像素检查失败卡到 60 秒。
- “跳过 / 进入 Codex”和 Esc 绕过像素门槛。没有可用窗口时退出动画；不会再让跳过按钮反复进入同一个等待状态，也不重复 AppLaunch。
- 系统允许时自动交接。若拒绝自动激活，不再只显示最终失败页，而是明确显示“Windows 阻止自动切换，请点击右上角进入”，按钮变成“点击进入 Codex”。真实点击后重新请求交接；不采用输入线程挂接等方式强迫抢夺系统焦点。总超时仍保留。
- 最小化实例改用保存的正常窗口尺寸识别，恢复后继续绑定，避免把一个已有实例当成冷启动。
- 冷启动窗口一旦被身份校验通过就尽早对齐，不再额外等 0.6 秒稳定期后才开始对齐。正式交接仍要求稳定与响应。
- 保留动画画面直到交接，继续以实际客户端区域进行视觉绑定。原 EXE、配置、自定义 MP4、官方文件和快捷方式均未覆盖。

首次创建的官方窗口在被发现前可能已经按其记忆位置出现在副屏；更早对齐缩短了可见时间，但本版不能保证完全抹除这第一帧。不能把“避免硬性卡住”说成“保证冷启动无白底 Logo”。辅助检测失败后的可用性回退也可能露出官方应用的加载页面。

## 测试说明

标准自动测试：22 条几何/配置、68 条生命周期/多屏/辅助检测断言、33 条隔离入口断言通过；另有 605 个关键帧和 12 个放置案例。

新增验证：空白采样最多辅助等待 3 秒、明确进入操作直接绕过像素检测；真实最小化 Codex 仍可被发现；受控的延迟内容和永久不可用内容可完成有界回退。受控测试的激活结果有注入，不能当作真实系统焦点验证。

真实 EXE 曾完成约 7 秒播放与自动交接、退出码 0，确认前台窗口正确，无额外 AppLaunch。

另以测试宿主注入“自动激活拒绝”，用 computer-use 实际读取启动器按钮并点击“进入 Codex”。日志确认 `user-requested-handoff`、真实 `foreground-confirmed=True`、遮盖关闭、退出码 0。测试宿主为了能被 UI 窗口选择器发现，仅在该模式开启任务栏显示；交付 EXE 未开启任务栏显示。该次约 44 秒包含了操作员观察和点击时间，并非切换需要 44 秒。

完整桌面检查结果与每轮原始日志见 qa/。真正退出所有 Codex 后的新版冷启动、首次副屏闪窗以及逐帧无白底 Logo 尚需人工验收。当前聊天没有为了测试而强制关闭官方 Codex。

## 使用和回滚

先关闭其他版本的社区启动器，将本包独立解压，运行 DragonCodexBoot/DragonCodexBoot.exe。保持外部 launcher.json 与 media/startup.mp4 目录结构。版本日志为 0.2.4.0。

若自动切换被拒，请点击右上角“点击进入 Codex”。若无目标窗口，Esc 会退出动画；若应用窗口确实崩溃，本版不会无限重新启动官方应用。

不要覆盖原安装进行首次验收。回滚只需停止本包并使用旧 EXE。正式替换前备份原 EXE 和配置，媒体不必改动。本版新增或改变的配置不自动写回原安装，也不运行快捷方式集成脚本。
