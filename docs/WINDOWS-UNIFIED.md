# Windows 统一版 0.2.1.0

2026-10-27：用户确认旧测试包在未手动关闭 Codex 的情况下出现过闪退；后续多轮成功。旧验证结论应记录为“多屏与多轮成功，但仍存在间歇性失败”，不算所有验收通过。

## 一个入口的自动行为

只需运行 `DragonCodexBoot.exe`，不再区分 Primary / Secondary 包。

- 配置 `TargetDisplay=auto`：自动查找通过包身份、会话、顶层窗口、可见性、尺寸、响应和稳定性检查的 Codex 窗口。已有窗口时，动画跟随该窗口所在显示器；没有合格窗口时使用 Windows 主显示器。
- 有已有窗口就交接；没有窗口就只请求一次系统 AppLaunch。启动后出现窗口会继续自动识别，不依赖启动目录或 Explorer 所在屏幕。
- 检测到的窗口消失时继续等待其恢复，但不重复发起 AppLaunch，不无限重启可能崩溃的应用。
- 原有明确的 TargetDisplay（例如 `\\.\DISPLAY2`）仍可用于固定屏幕；空值保持固定主屏。自动模式会在本轮启动开始时选屏，随后不因窗口移动而追着跳屏。

MP4、launcher.json 仍是外部文件，便于保留和替换用户自定义动画；本包内媒体是原安装中的自定义 MP4 副本，不是仓库默认动画。

## 对故障路径的补充处理

旧包日志显示一次实际前台激活被拒，以及多次窗口消失后等待超时。用户表示未主动关闭。窗口消失本身不足以区分 Codex 进程退出、窗口重建、隐藏或被筛选；目前没有足够证据判定官方应用内部的崩溃原因。

本版让等待期间的动画继续播放，播放结束后显示等待提示，避免主动停在 HoldAt；前台激活失败在 1.5 秒内有限重试，仍失败则显示错误并退出。新增版本、入口异常及启动器单实例抑制日志，帮助定位“重复双击但没有新动画”。没有修改 Codex 官方文件。

## 实测

- 构建成功；22 条几何/配置、53 条生命周期/多屏、33 条隔离入口断言，以及 605 个关键帧案例、12 个放置案例通过。
- 同源码桌面宿主：主屏、副屏、自动选屏、短视频配置和注入的缺失窗口超时路径通过；真实播放约 7 秒，位置采样在目标物理 WorkingArea 内。
- 本包实际 EXE：从 PowerShell 以 Windows 为工作目录启动，自动找到已有 Codex，完整播放 7 秒后确认前台交接、退出码 0，没有再次 AppLaunch。
- 新版尚未重做真实冷启动、窗口意外退出、真实前台激活拒绝和 Explorer 全矩阵验收；旧版用户日志中的成功冷启动不能替代新版验证。不能宣称已修复所有间歇性故障。

## 使用与回滚

先解压到独立目录，保留 `DragonCodexBoot.exe`、`launcher.json`、`media/startup.mp4` 的相对结构，双击 EXE。日志在 logs/launcher.log。不要同时打开旧版和新版，否则单实例锁可能阻止第二次启动。

不需要安装脚本或更改快捷方式。原 `D:\Apps\DragonCodexBoot` 和已解压的旧测试包均未替换。

正式部署前备份原 EXE 和配置，再仅替换社区启动器 EXE；若希望自动选屏，仅把已备份配置的 TargetDisplay 改为 auto，保留其他字段及原 MP4。回滚恢复原 EXE 和备份配置即可。部署与完整人工验收方法也见历史说明 WINDOWS-REPAIR.md，但该文的双 profile 交付说明属于上一版。
